## 3. SEC and Sharadar comparison contract

The B1 comparison supports only the selected USD revenue field on SF1 `ARY`,
with an optional `ARQ` Q1 candidate when a separate exact source witness
establishes direct discrete-quarter grain and matches the parsed SEC and SF1
facts. An SF1 row alone does not establish Q1 grain; an unproven Q1 is
unavailable. B1 does not implement Q2/Q3/Q4 quarterization; those plan roles
are unavailable in this checkpoint. Any later support would require compatible
same-fiscal-year YTD components with separately bound lineage for Q2/Q3, or
annual less same-year Q3 YTD with both exact components bound for Q4. Adjacent
rows are not quarterized by inference. `ART` is not four original-quarter
facts, and `MRQ`/`MRY`/`MRT` are rejected for historical PM2C facts.

A candidate match requires exact or explicitly normalized agreement for the
issuer, accession lineage, report/fiscal period, period type, concept and
normalized field mapping, context and dimensions, security scope, unit,
currency, scale, sign, value, SF1 As Reported dimension, source version and
availability boundary. Names and numbers alone are insufficient. Custom
dimensions, conflicting/duplicate records, missing/null values, unsupported
fields, and mismatched units or identity fail closed. A true zero remains a
value and is never substituted for null or missing data.

Keep separate the economic period, SEC acceptance timestamp, filing date,
public-availability witness, Sharadar `datekey`, Sharadar `lastupdated`, local
observation time and calculation time. Period end is not publication;
`datekey` is not proof that an exact vendor-normalized value existed then; and
`lastupdated` is not an immutable version witness. A Sharadar fact cannot
inherit SEC availability automatically. An amendment is a later version and
must not rewrite the original. An earlier 8-K can establish lineage only when
its accession proves the same exact fact, basis and value with its own public
availability witness.

## 4. Evidence and attempt truthfulness

Each fake response is bound to a safe request identity, exact content bytes,
length, SHA-256, content type where available, observation time, provider
record identity, record/page counts and terminal pagination state. Custody
paths are storage locations, not semantic identity. A digest proves byte
identity, not historical availability.

The bounded attempt is reserved once with no automatic retry. The terminal
manifest distinguishes source-admission attempts, SEC and Sharadar attempts,
documents/pages/records inspected, custody writes, comparison attempts,
credential reads, account reads, AI calls, broker effects and production
mutations. Provider-attempt counters increment before invocation so a provider
exception cannot be reported as zero attempts. Credentials and unsafe request
URLs are never persisted; raw provider errors are not exposed in evidence.

Typed terminal outcomes distinguish qualified candidates, mismatches,
unproven versions/availability, unsupported contexts/fields, missing facts or
rows, conflicts, page/attempt limits, source-admission failure, evidence-write
failure, provider failure and invalid fake boundaries. No failure silently
becomes an empty successful result.
